# Dual-Controller Security Architecture for Cyber-Physical Systems

This repository contains the MATLAB/Simulink implementation of a **Parallel Dual-Controller Defense Framework** designed to detect stealthy cyber-attacks in Cyber-Physical Systems (CPS). 

By evaluating discrepancies between two parallel control signals ($u_a$ vs. $u_b$) under a time-varying parameter $a(t)$, this framework exposes hidden attacks and sensor spoofing attempts.

---

## 📌 Project Overview

Standard single-loop control systems are vulnerable to **sensor spoofing and false data injection (FDI) attacks**. An adversary can manipulate physical plant dynamics while feeding corrupted or "flat" nominal feedback data back to the primary controller to bypass standard anomaly checks.

This project implements a **Dual-Controller Architecture** that monitors the internal control effort discrepancies between:
1. **Controller A ($u_a$):** The primary controller receiving feedback across the network.
2. **Controller B ($u_b$):** The isolated, trusted shadow controller running locally.

---

## 🏗️ Key System Features

* **Control Effort Cross-Checking:** Anomaly detection is performed at the control signal level by computing the deviation between $u_a$ and $u_b$.
* **Time-Varying Parameter $a(t)$:** The physical plant relies on a dynamic, changing parameter $a(t)$. An adversary without real-time knowledge of $a(t)$ uses an incorrect zero in their attack law.
* **Isolated Shadow Loop:** Controller B operates inside a local software environment, making its reference trajectory ($u_b$) inaccessible to network-based attackers.
* **Noise-Tolerant Thresholds:** Tuned parameters ensure that true attack discrepancies produce clear spikes above background measurement noise without generating false alarms.

---

## 📐 Detection Logic & Mathematical Framework

The residual alert is generated directly from the discrepancy between the two control signals:

$$\text{Residual } (\Delta u) = |u_a - u_b| > \text{Threshold}$$

Where:
* **$u_a$** = Control effort generated by Controller A.
* **$u_b$** = Control effort generated by Controller B (Shadow Controller).

### Why the Adversary Cannot Stay Hidden

1. **Without Sensor Spoofing:** Because the attacker does not know the dynamic parameter $a(t)$, the wrong zero in their attack law causes structural pole-zero mismatch. Physical output explodes, forcing Controller A ($u_a$) to diverge rapidly from $u_b$.
2. **With Sensor Spoofing:** If the attacker spoofs network feedback to make the plant look stable, Controller A ($u_a$) responds to the manipulated feedback, causing its output to immediately mismatch with the isolated shadow control signal ($u_b$).

> **Result:** Stealthy attacks become impossible because the attacker cannot reconcile $u_a$ with $u_b$ simultaneously.
